# Práctica 1: Mi primer repositorio en GitHub

## Preguntas de comprensión

### 1. ¿Qué diferencia hay entre confirmar (commit) y subir (push)?

Confirmar sirve para guardar los cambios en el historial del repositorio de nuestro ordenador, mientras que subir sirve para enviar esos cambios a GitHub.

### 2. ¿Qué significan 1↑ y 1↓ en la barra de estado de VS Code?

1↑ significa que tenemos un commit pendiente de subir a GitHub y 1↓ significa que tenemos un commit pendiente de descargar desde GitHub.

### 3. ¿Por qué en esta práctica usaste un repositorio privado y un correo noreply?

Para proteger nuestros datos personales. El repositorio privado evita que otras personas puedan acceder sin permiso y el correo noreply evita mostrar nuestro correo real en los nuevos commits.

### 4. ¿Por qué la copia clonada no mostraba un cambio hecho en GitHub hasta que sincronizaste?

Porque cada copia del repositorio es independiente y necesita sincronizarse para recibir los cambios que se han hecho en GitHub.

### 5. ¿Qué hace la palabra Closes seguida de un número en la descripción de una Pull Request?

Hace que el Issue con ese número se cierre automáticamente cuando se fusiona la Pull Request en la rama principal.

### 6. ¿Por qué es mejor trabajar en una rama y fusionarla mediante Pull Request que editar main directamente?

Porque podemos hacer cambios sin afectar a la rama principal y revisar que todo funciona correctamente antes de incorporar los cambios a main.
